# Chrome 实验使用说明

1. 每次电脑重启后，双击本目录的“启动实验服务.cmd”。它启动本机 API（8000）和被动 USB 波形服务（8011），已经运行的服务不会重复启动。
2. 打开 https://doc-b-yang.github.io/heart-companion/ 。Chrome 若询问本地网络访问，允许这个网站访问本机服务；也可在地址栏左侧的网站设置中调整。分析后端地址为 http://127.0.0.1:8000，波形服务为 http://127.0.0.1:8011。
3. 蓝牙选取 HeartCompanion 后，新版正式固件同时提供 PPG 与 GSR 波形。USB 与蓝牙可同时工作；USB 服务不再替换固件、也不再在 10 分钟后退出。不要同时用串口监视器占用 ESP32 的 USB 串口。USB 串口断开后服务会等待重连。
4. MAX30102 和 GSR 贴稳、手臂和 MPU 静置后，点击“已佩戴好电极”。按钮可以点击，但服务器仍要求新鲜真实数据才能确认此次佩戴。保持静息约 3 分钟；只有合格窗口才允许保存基线。
5. 自评文字、唤醒度和愉悦度可独立保存，不要求波形质量合格。后端离线时，输入保留并显示连接问题；恢复后再点击保存。自评保存不等于已创建合格的分类训练样本。

## 效价、唤醒度和陪伴

1. 回想刚过去的60秒，在“唤醒度”和“愉悦度”中分别选择1～9分，再点击“保存自评”。唤醒度是激活程度，愉悦度是感受是否愉快，两者可以不同；不想评分的轴保持“暂不评分”。原有感受名称仍可保存，但不会自动换算成两轴分数。
2. “效价与唤醒度”面板显示评分和来源。1、5、9分分别换算为−1、0、1。两轴都有有效依据才显示二维点，缺失轴显示未知；新一轮自评未填写的轴不继承上次评分。
3. 想让AI辅助理解表达时，在“感受文字”写下当前自己的感受，点击“分析这段感受”；也可以在聊天框输入并点击“发送”。文字分析只辅助估计效价，不替你填写唤醒度。分析按钮不保存自评，也不创建分类训练标签；需要记录本人评分时仍点击“保存自评”。
4. 有效的本人评分优先。自评与语言推测差异较大时保留提示和各自来源，坐标使用自评；它们可能描述不同时间范围。主观展示依据5分钟后过期，持久保存的自评记录仍在，但不一直代表当前感受。后端重启后需重新填写或表达。
5. AI语言分析需要本机后端连接可用的在线AI服务；离线、表达不足或分析失败时显示未知，可以继续填写本人评分。这里的数值是主观参考，未经识别准确率验证，不能当作生理分类结果、医学诊断或已验证PAD。

进行独立分类实验时，先评分、保存，再查看AI分析和模型解释，避免显示结果影响实验标签。个人高/低唤醒模型目前仍是离线实验路线，主观面板出现坐标不表示该模型已接入网页。

## 中文语音输入

1. 在聊天或“感受文字”旁点击“语音输入”，按Chrome提示允许麦克风，然后说出当前感受。只有点击后才开始识别，界面会显示识别预览。
2. 说完等待识别结束，或点击“停止并写入”。完整转写写入原有输入框；检查并修改文字后，手动点击“发送”“分析这段感受”或“保存自评”。识别过程不会自动提交。
3. “取消语音”不提交转写并保留原有文字。麦克风权限、网络或浏览器语音服务不可用时，按提示处理或继续打字；语音是可选输入方式。

此功能使用Chrome的 `zh-CN` 语音识别，将语音转成文字后分析语义，未分析声调、韵律或音频情绪。项目不录制或保存原始音频，但浏览器语音服务可能在线处理音频；点击分析或发送后，该条文字可能发送给后端配置的AI服务。本机保存的生理数据、自评和聊天不上传到GitHub，不能因此理解为所有处理都只发生在本机。

本机新功能需先运行更新后的后端；固定GitHub Pages网址还需部署更新后的网页。若公网页面没有以上按钮和面板，应先确认部署版本，再用Chrome强制刷新（Ctrl+Shift+R）；浏览器缓存不能替代部署。

PPG 图显示实际红外 ADC 的 25 Hz 显示采样，并在浏览器去直流；心搏分析仍使用完整传感器采样。USB CSV 保存显示采样，BLE 下载保存接收的数据包。这些文件不能当作完整 100 Hz 原始数据。断段和时间缺口不连线，历史波形不表示正在采集。

信号质量不足时仍能观察、下载真实波形；界面不因此宣称已经准确识别情绪。GSR 当前记录模块输出电压，尚非经过电导校准的数值。是否形成合格训练样本以保存响应和质量检查为准，AI语言估计永不自动作为训练标签。
